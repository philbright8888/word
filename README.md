# Word 银行对账单独立工具集

本仓库不是一个把所有功能合并起来的“大一统程序”，而是**多个互相独立的工具**。每项任务使用自己的 Python 文件，必要时有自己的说明页和运行命令。

## 工具列表

| 独立工具 | 独立代码 | 专属说明 |

| 表头前插入3行×4列无边框区域 | [insert_3x4_before_bank_header_no_borders_mac.py](scripts/insert_3x4_before_bank_header_no_borders_mac.py) | [查看说明](docs/tools/insert-3x4-before-bank-header.md) |

当前仓库只导入了上表列出的这一项实际工具。其他在聊天中讨论过的格式统一、银行信息边界对齐、汇总行整理、重复内容清理和 VBA 工具，后续应当**各自保留为单独文件**，逐项导入；不会把它们塞进同一个脚本，也不会让某个工具自动执行其他工具的功能。

## 目录约定

- `scripts/<工具名>.py`：每个工具一个独立 Python 文件，可单独运行。
- `docs/tools/<工具名>.md`：每个工具一份独立说明，写清适用场景、执行范围、不执行的操作、运行方法及输出文件。
- `docs/PROJECT_SPEC.md`：项目整体约束，仅用于说明，不代表所有工具都要执行每条规则。
- `docs/USAGE.md`：通用运行和验收建议。

## 工具独立性原则

1. **一个任务一个工具**：例如“插入3行×4列”“统一全文字体”“银行信息表左右对齐”“汇总行固定排版”应分别实现。
2. **不默认联动**：运行插入工具，不应顺便改字体、列宽、汇总行或删除段落。
3. **单独运行、单独输出**：每个脚本有自己的入口、输入选择和输出命名。
4. **明确写出限制**：说明页列出工具不会做什么，防止误用。
5. **不要凭需求记录伪造源码**：只有实际导入并验证存在的脚本，才列为可用工具。

## 隐私与安全

- 不提交真实银行对账单、账号、交易金额、测试 DOCX 或包含交易数据的扫描报告。
- 原文件不覆盖、不删除；输出到新文件。
- 遇到复杂合并单元格或无法确定的分页结构时，应跳过并记录，而不是猜测性修改。
- 模拟测试不能替代在 Microsoft Word/WPS 中核对真实文档。

## 每个工具都必须有使用说明

新增工具时必须同时提供专属说明页，包含适用场景、不会做什么、输入要求、依赖安装、运行命令、输出文件、限制和验收清单。参考 [工具说明模板](docs/tools/TOOL_TEMPLATE.md) 和 [通用使用规范](docs/USAGE.md)。

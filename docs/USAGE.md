# 使用说明与工具文档规范

本项目包含多个互相独立的 Word/WPS 工具。**每个工具单独运行、单独说明、单独输出；不得将所有功能合并进一个脚本，也不能默认一个工具执行其他工具的规则。**

## 使用前先选工具

1. 打开仓库首页的工具列表。
2. 点击目标工具的专属说明页。
3. 确认“适用场景”和“不会做什么”。
4. 按该工具页面提供的环境、安装和运行命令操作。
5. 运行后按页面中的验收清单检查结果。

## 环境

个别 Python 工具可能需要 Python 3 和 `python-docx`。只有在对应工具说明页列出依赖时才安装：

```bash
python3 -m pip install python-docx
```

不同工具可能有不同依赖；不要假设所有工具使用完全相同的环境。

## 每个工具都必须有独立说明页

新增工具源码时，必须同时新增 `docs/tools/<工具名>.md`，至少说明：

- **用途与适用场景**：什么时候应该运行。
- **不会做什么**：明确列出不涉及的功能。
- **输入要求**：支持的文件类型、当前目录选择方式、前置条件。
- **安装依赖**：只列出该工具实际需要的依赖。
- **运行命令**：提供可复制的完整命令。
- **处理规则**：具体会修改什么、保留什么。
- **输出说明**：输出文件名、日志位置、是否覆盖原文件。
- **限制与风险**：无法识别或不安全时如何处理。
- **验收清单**：用户如何在 Word/WPS 中检查结果。

同时更新仓库根目录的 `README.md` 工具目录，提供源码和说明页的链接。只有源码确实存在并已提交的工具才能列为可用工具；不能只根据聊天中的讨论创建虚假的工具条目。

## 独立性规则

- 一项明确任务对应一个独立脚本或宏。
- 插入空白行的工具不得顺便统一字体、改列宽或清理段落。
- 字体统一工具不得默认删除汇总行或插入单元格。
- 银行信息对齐工具不得默认执行全文格式处理。
- 汇总行工具不得修改动态金额或其他交易内容。
- 若用户需要组合工作流，应另行明确创建一个调用多个独立工具的工作流；各工具本身仍保持独立。

## 原件与隐私

- 不提交真实银行对账单、账号、交易金额、测试 DOCX 或包含交易数据的扫描报告。
- 默认输出到新文件，不覆盖、不删除原件；若输出文件已存在，停止或要求用户另选名称。
- 对复杂合并单元格、非标准网格、分页不确定或图片定位不明确的文档，应跳过并记录原因。
- 模拟测试不能替代在 Microsoft Word/WPS 中检查真实文档。

# 项目规格说明

## 项目目标
自动处理银行对账单 DOCX：统一文字格式、识别标准11列表头、处理复杂合并单元格、清理重复表头/页脚、对齐银行信息区域，并尽量保护交易数据与图片。

## 标准11列
1. No.
2. Bk.D.
3. Val.D.
4. Type
5. Vou.
6. Vou.No./Trans.No./Details
7. DebitAmount
8. CreditAmount
9. Balance
10. ReferenceNo.
11. Notes

## 排版约束
- 全文文字8磅；中文宋体；英文和数字 Times New Roman。
- 字符缩放100%，字符间距和字符位置均为0。
- 标准11列表头居中；交易内容按列设置对齐。
- 非标准单元格左对齐、段落缩进为0、左右内边距为0，并清理多余空格、Tab、手动换行和空白段落。
- 标准表格列宽保持统一；Details 应略宽于 Notes。
- 银行信息表的左右外边界应与对应标准表格一致。
- 四组金额汇总项 Debit Total、Credit Total、This Page Balance、Closing Balance of This Reconciliation 应按固定位置尽量保持在同一行；金额动态变化且必须原样保留。
- 不能因为扫描器未识别表头或底层网格数量不等于11就删除有效列。

## 图片和原件保护
- 原始 DOCX 不覆盖、不删除。
- 输出新文件；已存在的输出文件不覆盖。
- 不主动修改、缩放、移动或删除图片；保留锚点、环绕方式和定位属性。
- 遇到无法安全判断的复杂结构时应跳过并写日志，而不是猜测或强制重构。

## 独立插入工具
scripts/insert_3x4_before_bank_header_no_borders_mac.py：
- 识别标准11列表头。
- 满足条件时在表头前插入3行×4个逻辑单元格。
- 新增区域无边框；原表格列宽、交易内容、图片不主动修改。
- 不删除任何原有内容。
- 当前目录按编号选择 DOCX。
- 输出“原文件名_插入3行4列.docx”，不覆盖原件。

## 验证注意事项
DOCX 的底层 XML 宽度与 Word/WPS 最终视觉宽度可能不同。复杂合并单元格和分页必须在目标 Word/WPS 中检查。模拟测试不能替代真实文档版面验收。

## 隐私
不要提交真实银行对账单、账户号码、交易金额、原始 DOCX、含交易数据的扫描报告或测试输出文件。
